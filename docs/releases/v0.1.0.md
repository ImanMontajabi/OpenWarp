# OpenWarp 0.1.0: first MVP release

OpenWarp is an independent, open-source macOS client for the Cloudflare WARP consumer network: a background
daemon written in Go, an `openwarp` command-line tool and a native SwiftUI app. This is the first public
release. It is an MVP: expect rough edges, and read the limitations below.

> OpenWarp is **not affiliated with, endorsed by or supported by Cloudflare, Inc.** It connects to
> Cloudflare's public WARP service, so using it means accepting the
> [Cloudflare WARP Terms of Service](https://www.cloudflare.com/application/terms/).

## What's in it

- **Native macOS app** with a dark, minimal design: Home, Connectivity, Settings, Profile and About.
- **Connect with the cloud**: the cloud on Home connects and disconnects and shows the connection state.
- **Seven connection modes**, as in the official client: Traffic and DNS over UDP, HTTPS or TLS; DNS only over
  HTTPS or TLS; Traffic only; and a Local proxy (SOCKS5/HTTP) that needs no administrator rights.
- **MASQUE** (HTTP/3, with optional post-quantum key agreement) and **WireGuard** tunnels.
- **Settings**: split tunnel, local domain fallback, 1.1.1.1 for Families, trusted networks, proxy port,
  endpoint override, key rotation, WARP+ license keys and the device list.
- **Menu bar dashboard**: status, a connect button, live upload and download rates with session totals
  (measured from real traffic counters), and the public IP, country and Cloudflare data centre that
  Cloudflare reports.
- **First-run setup**: the app explains the background service and installs it after macOS's own
  administrator prompt (OpenWarp never sees your password), then checks that it is running before it
  continues. It offers to update an outdated service. The Terminal commands remain available as an alternative.
- **Update checks**: once a day the app asks GitHub whether a newer release exists, and links to it. Nothing is
  downloaded or installed automatically. You can switch this off in Settings → Updates.

## How well it is tested

| Area | Status |
|---|---|
| Registration, MASQUE and WireGuard in Local proxy mode | Verified live against Cloudflare |
| Traffic and DNS (UDP) mode | Used by the author on one Apple silicon Mac |
| Other root modes (HTTPS/TLS DNS, DNS only, Traffic only) | Implemented; not yet verified end to end |
| Service install, restart, upgrade and uninstall from the DMG | Tested automatically on a clean CI Mac (no VPN connection made) |
| In-app installer with the administrator prompt | Covered by UI tests with a simulated prompt |
| App UI (tabs, modes, dashboard, onboarding, settings) | Unit, snapshot and UI tests in CI |
| Intel Macs | Universal build; the Intel code is built and checked but not tested on Intel hardware |

## Requirements

- macOS 14 Sonoma or later.
- Apple silicon or Intel (universal app).
- Administrator rights to install the background service, which the full-device modes need. Local proxy mode
  works without it.

## Install

1. Download `OpenWarp-v0.1.0-macos-universal.dmg` from this release and check it against `SHA256SUMS.txt`:
   `shasum -a 256 -c SHA256SUMS.txt` in the download folder.
2. Open the DMG and drag **OpenWarp** into **Applications**.
3. Open OpenWarp from Applications.
4. OpenWarp is not signed with an Apple Developer ID and not notarized, so macOS may refuse to open it
   ("Apple could not verify…"). Open **System Settings → Privacy & Security**, scroll to Security, click
   **Open Anyway** next to the OpenWarp message, and confirm. You need to do this once. The wording and steps
   differ between macOS versions, and managed Macs may not allow it.
5. Follow the first-run screen to install the background service.

Never turn off Gatekeeper to run OpenWarp; the steps above are enough.

To remove OpenWarp: `sudo /Applications/OpenWarp.app/Contents/Resources/openwarp service uninstall`, then move
the app to the Bin. Your registration stays in `/Library/Application Support/openwarp`.

## Known issues and limitations

- **No Developer ID signature or notarization.** The app is ad-hoc signed. Gatekeeper warns on first launch (see
  above), and the in-app installer trusts the app bundle it runs from: install only from this release page or
  from your own build.
- **No Network Extension.** Full-device modes change routes and DNS with `route` and `networksetup`. If the
  daemon is killed while connected, DNS settings may need to be restored by hand.
- **Trusted Wi-Fi by name** needs Location permission, which OpenWarp does not request yet; the "all Wi-Fi" and
  "all wired networks" switches work.
- **Location** comes from Cloudflare's trace and is a country and data centre, not a city.
- **Unofficial API.** OpenWarp uses Cloudflare's undocumented client API, which can change at any time, and
  whether WARP works depends on the network you are on. OpenWarp does not promise higher speed or access to any
  particular site.
- The daemon's local control socket accepts commands from every user account on the Mac.
- Not included: Zero Trust / Teams, MDM, the HTTP/2 fallback for MASQUE and hostname-based split tunnelling.

## Privacy

OpenWarp contacts Cloudflare's WARP API and edge (that is the service), `www.cloudflare.com/cdn-cgi/trace` for
the dashboard's public IP (switch off in Settings → Privacy) and `api.github.com` for update checks (switch off
in Settings → Updates). It has no analytics or telemetry.
