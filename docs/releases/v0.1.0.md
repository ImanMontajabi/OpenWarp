# OpenWarp 0.1.0: first public release

OpenWarp is an independent, open-source macOS client for the Cloudflare WARP consumer network. It has three parts: a background daemon written in Go, an `openwarp` command-line tool and a native SwiftUI app. This is the first public release. It is an MVP: expect rough edges, and read the limitations below.

> OpenWarp is **not affiliated with, endorsed by or supported by Cloudflare, Inc.** It connects to Cloudflare's public WARP service, so using it means accepting the [Cloudflare WARP Terms of Service](https://www.cloudflare.com/application/terms/).
>
> **It is not an anonymity tool.** It hides your traffic and DNS from the network you are on. Cloudflare sees your real IP address and where your traffic goes. OpenWarp does not protect you from being identified, and it does not guarantee that nothing leaks.

## What's in it

- **Native macOS app**: Home, Connectivity, Settings, Profile and About, plus a menu bar dashboard (status, connect, live rates, public IP/country/data centre as Cloudflare reports them).
- **Seven connection modes**, as in the official client:
  - Traffic and DNS over UDP, HTTPS or TLS;
  - DNS only over HTTPS or TLS;
  - Traffic only;
  - a Local proxy (SOCKS5/HTTP) that needs no administrator rights.
- **MASQUE** (HTTP/3, optional post-quantum key agreement) and **WireGuard** tunnels.
- **Leak protection**:
  - IPv6 is blocked when the tunnel has no IPv6.
  - Routes and DNS are restored after a crash.
  - `sudo openwarp recover` fixes routes and DNS by hand.
  - Connection verification (`openwarp verify`, Verify in the app) checks the routes and DNS, and optionally asks Cloudflare whether the connection goes through WARP.
- **Kill switch (experimental, off by default)**: pf rules that block traffic outside the tunnel while a connection is wanted, including during reconnects and service restarts. See the limitations below.
- **A protected background service**:
  - Any local account can read the status.
  - Only root, administrators and the account that installed the service can connect, disconnect, change settings (including the kill switch) or read the registration and licence key.
- **First-run setup**: the app installs the background service after macOS's own administrator prompt. OpenWarp never sees your password.
- **Update checks**: once a day the app asks GitHub for a newer release. It never downloads anything, and you can switch this off.

## How well it is tested

| Area | Status |
|---|---|
| Registration, MASQUE and WireGuard in Local proxy mode | Verified live against Cloudflare |
| Traffic and DNS (UDP) mode | Used by the author on one Apple silicon Mac |
| Kill switch | Rules and lifecycle tested offline (fake pfctl, real `pfctl -n` parsing). The live leak test (`scripts/leak-test.sh`) ran once on one Apple silicon Mac (Wi-Fi, warp mode, MASQUE) against the build just before this release: no probe got around the tunnel, including 29 probes during a daemon kill and restart. Its 3 failed checks led to fixes in this release (see below); the fixed build has not been run through it yet. |
| Control-socket authorization | Tested automatically with a real socket and kernel peer credentials; not checked by hand on a real Mac |

## Requirements

- macOS 14 Sonoma or later.
- Apple silicon or Intel (universal app).
- Administrator rights to install the background service, which the full-device modes need. Local proxy mode works without it.

## Install

1. Download the DMG and `SHA256SUMS.txt`, and check them: `shasum -a 256 -c SHA256SUMS.txt`.
2. Open the DMG and drag **OpenWarp** into **Applications**, then open it from Applications.
3. OpenWarp is **ad-hoc signed: it has no Apple Developer ID signature and is not notarized**, so macOS refuses to open it at first ("Apple could not verify…").
   - Open **System Settings → Privacy & Security**, find the OpenWarp message under Security, click **Open Anyway** and confirm. You only need to do this once.
   - The wording differs between macOS versions, and managed Macs may not allow it.
   - **Never turn off Gatekeeper to run OpenWarp.**
4. Follow the first-run screen to install the background service.

**Uninstall:** run `sudo /Applications/OpenWarp.app/Contents/Resources/openwarp service uninstall`, then move the app to the Bin. Uninstalling also removes the kill switch rules and restores routes and DNS. Your registration stays in `/Library/Application Support/openwarp`.

## Known issues and limitations

- **No Developer ID signature or notarization.** The in-app installer trusts the app bundle it runs from, so install only from this release page or from your own build.
- **The kill switch is experimental.**
  - While it is on, its rules end pf's evaluation for the traffic it lets through (the tunnel, the local network, loopback), so other pf-based firewalls on the Mac, such as per-app blockers, do not apply to that traffic.
  - It uses pf (no Network Extension). Root (or an administrator) can change pf behind it. OpenWarp re-applies its rules within about 5 seconds and reports problems in verification.
  - On purpose, it lets through: the connection to Cloudflare's edge, the API fallback addresses, DHCP/IPv6 neighbour discovery and your split-tunnel exclusions (by default the local network).
  - Turning it on flushes pf's connection states, which also resets Internet Sharing connections.
  - It is not used in Local proxy mode, the DNS-only modes or with Include split tunnelling.
  - If it ever leaves you without a connection, disconnect, or run `sudo openwarp recover`.
- **No Network Extension.** Full-device modes change routes and DNS with `route` and `networksetup`.
- Development builds before this release could delete macOS's own `169.254` link-local route (or a LAN route equal to a split-tunnel exclusion) on disconnect. This release fixes it; if the route is still missing on your Mac, turn Wi-Fi off and on.
- **Trusted Wi-Fi by name** needs Location permission, which OpenWarp does not request yet. The "all Wi-Fi" and "all wired networks" switches work.
- An account that is neither an administrator nor the one that installed the service can only see the status in the app. Settings it cannot read show their default values.
- **Unofficial API.** OpenWarp uses Cloudflare's undocumented client API, which can change at any time. OpenWarp does not promise speed or access to any particular site.
- Not included: Zero Trust / Teams, MDM, the HTTP/2 fallback for MASQUE, hostname-based split tunnelling.

## Privacy

OpenWarp contacts only these services:
- Cloudflare's WARP API and edge (that is the service itself);
- `www.cloudflare.com/cdn-cgi/trace` for the dashboard's public IP (switch off in Settings → Privacy);
- `api.github.com` for update checks (switch off in Settings → Updates).

It has no analytics or telemetry. Details: [Privacy and leak protection](https://github.com/ImanMontajabi/OpenWarp/blob/release/docs/privacy-and-leak-protection.md).
